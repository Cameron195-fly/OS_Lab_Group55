# 本实验未覆盖的操作系统知识点

> 本节由丙（2412440-王朝阳）整理。Lab4 只实现了“物理页管理 + 进程创建 + 协作式轮转”的最小闭环，
> 下面列出与真实操作系统差距较大的知识点，并说明本实验的现状与真实系统的做法。

## 6.1 用户态与特权级切换

**本实验现状：** 所有进程都运行在 S 模式（内核态），`kernel_thread()` 直接执行内核函数，
没有 U 模式，没有系统调用，也没有用户地址空间隔离。`idt_init()` 里设置
`SSTATUS_SUM` 只是允许 S 模式访问用户页，本实验并没有真正运行用户程序。

**真实系统需要：**

- U/S 模式切换，`ecall` 系统调用入口与返回值约定，系统调用号分派；
- 用户栈与内核栈分离，进入内核时切换栈指针；
- `fork/exec/wait/exit` 的用户态语义，进程地址空间隔离与权限位（R/W/X/U）；
- 内核态访问用户指针时的合法性检查（`copy_from_user` / `copy_to_user`），防止内核被用户指针攻击。

## 6.2 抢占式调度与调度策略

**本实验现状：** `schedule()` 只实现最朴素的轮转；调度点是 `cpu_idle()` 的循环和测试代码的显式调用。
时钟中断只做 `clock_set_next_event()` 续期、`ticks++` 与每 100 tick 打印，**没有**把
`current->need_resched` 置 1；Trap 返回路径上也**没有**检查 `need_resched` 并触发抢占。

**真实系统需要：**

- 时间片（quantum）与抢占：时钟中断里设置 `need_resched`，中断返回前检查并在需要时切换；
- 优先级调度、多级反馈队列、CFS/EEVDF 等公平调度算法，以及 nice 值/权重；
- 实时调度策略（SCHED_FIFO / SCHED_RR）与优先级反转问题；
- 负载均衡、CPU 亲和性、调度域；
- 睡眠/唤醒队列，避免 `cpu_idle()` 这种忙等，空闲时执行 `wfi`。

## 6.3 进程同步与通信

**本实验现状：** 只有 `local_intr_save/restore` 这种“关中断”临界区，
没有信号量、互斥锁、条件变量、等待队列，也没有进程间通信。
`wakeup_proc()` 只是一个把状态改成 `PROC_RUNNABLE` 的函数，没有配套的睡眠队列。

**真实系统需要：**

- 信号量/互斥锁/读写锁/自旋锁，睡眠锁与原子锁的取舍；
- 条件变量、等待队列、`wait_event` / `wake_up`；
- 生产者—消费者、读者—写者、哲学家就餐等经典同步问题；
- 死锁的四个必要条件、预防/避免/检测（银行家算法）、锁顺序规范；
- 进程间通信：管道、消息队列、共享内存、信号、socket；
- 无锁数据结构与内存序（`fence`、RCU）。

## 6.4 内存管理进阶

**本实验现状：** 模块一实现了物理页分配/释放、页表项读写与映射建立，
模块二为每个进程建立了一份内核页目录拷贝；但所有进程共享同一份内核映射，
没有用户地址空间，也没有按需分页。

**真实系统需要：**

- 缺页异常处理：按需分页、栈自动增长、写时复制（COW）；
- 页面置换算法（LRU/Clock/工作集）、swap；
- 内存映射文件（`mmap`）、共享内存、页缓存；
- 大页、TLB 管理与 shootdown、反向映射；
- 内存碎片、伙伴系统/ slab 分配器、NUMA；
- 虚拟地址空间布局、ASLR、栈保护。

## 6.5 文件系统与设备管理

**本实验现状：** 没有文件系统，没有块设备驱动，没有 VFS。
输入输出只靠 SBI 的 `sbi_console_putchar` / `sbi_shutdown`。

**真实系统需要：**

- 块设备驱动、中断与 DMA、磁盘调度（电梯算法）；
- 文件系统：inode、目录项、超级块、日志/崩溃一致性、ext4/FAT 等；
- VFS 抽象：`open/read/write/close`、文件描述符表、页缓存与回写；
- 设备树、总线模型、字符设备/块设备/网络设备；
- 权限、配额、快照、加密文件系统。

## 6.6 中断控制器与外设中断

**本实验现状：** 只处理 S 模式时钟中断、软件中断和外部中断的“打印”分支；
外部中断没有接 PLIC，也没有具体设备中断源。

**真实系统需要：**

- PLIC/APIC 等中断控制器：中断源优先级、使能、claim/complete；
- 中断亲和性、中断线程化、中断下半部（softirq/tasklet/workqueue）；
- 设备树解析、驱动注册与探测；
- 中断风暴抑制、中断延迟与实时性。

## 6.7 多核（SMP）与并发

**本实验现状：** 单 hart 运行，`local_intr_save` 只屏蔽本核中断；
全局变量 `current`、`proc_list` 都没有多核保护。

**真实系统需要：**

- 每个 CPU 的 `current`、运行队列、idle 进程；
- 自旋锁、每 CPU 变量、原子操作、内存屏障；
- CPU 热插拔、负载均衡、IPI（核间中断）；
- TLB shootdown、全局页表同步；
- 多核启动（spin-table / SBI HSM）与 per-CPU 初始化。

## 6.8 上下文切换的完整性

**本实验现状：** `switch_to` 只保存 `ra, sp, s0~s11` 共 14 个 callee-saved 寄存器，
这是“内核线程之间切换”的最低要求。没有浮点/向量寄存器，没有 FPU 状态。

**真实系统需要：**

- 浮点/向量上下文（`f0~f31`、`v0~v31`）的惰性保存与恢复；
- 用户态与内核态切换时的完整寄存器现场；
- 栈保护页、栈溢出检测、红区处理；
- 上下文切换开销的度量与优化（如 `lazy TLB`、PCID/ASID）。

## 6.9 可靠性与安全

**本实验现状：** `panic()` 直接打印并进入死循环；没有异常恢复、没有日志、没有权限检查；
`assert()` 失败即崩溃。

**真实系统需要：**

- 内核崩溃转储（kdump）、日志与追踪（ftrace/perf）；
- 错误注入与恢复、看门狗；
- 权限模型（capability、LSM）、地址空间隔离、SMEP/SMAP/PAN；
- 栈金丝雀、KASLR、W^X、控制流完整性；
- 单元测试、压力测试、形式化验证。

## 6.10 本实验测试本身的局限

评分测试只验证：

1. PMM 能分配/释放物理页并正确建立映射；
2. `proc_init()` 能创建 idleproc/initproc，`kernel_thread()` 能创建可运行线程；
3. 连续 8 次 `schedule()` 后两个测试线程都至少运行过一次。

它**没有**验证：

- 调度的公平性、顺序、时间片长度；
- 优先级、饥饿、实时性；
- 多核并发下的正确性；
- 长时间运行的内存泄漏与栈溢出；
- 中断/异常路径的覆盖率。

因此“30/30”只说明最小闭环正确，不等于调度器已经达到生产级质量。

## 6.11 小结

Lab4 的价值在于把“进程”从一个概念变成可运行、可切换的实体：
PCB、内核栈、trapframe、页目录、上下文、调度队列，这些部件第一次完整地串了起来。
但从“能轮转”到“能支撑真实应用”，还差用户态、抢占、同步、文件系统、多核与安全等大量机制。
这些正是后续课程实验与真实操作系统（Linux/RT-Thread 等）继续展开的内容。
